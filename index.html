Authenticator apps (like Google Authenticator) make a new six-digit code every 30 seconds, even in aeroplane mode. Nothing is sent to your phone. Your phone and the website each hold the same secret and read the same clock, so they can each work out the same number on their own.

  1. 1

    The shared secret

    At setup, the website makes a random 160-bit secret and shows it to you once, inside a QR code. Your app saves it. It's written in Base32, letters A–Z and digits 2–7.

    Base32
    As bytes (hex)
  2. 2

    Turn the time into a counter

    Take Unix time, the seconds since 1 January 1970 in UTC, so time zones don't matter. Divide by 30 and round down. Every 30 seconds the counter goes up by one.

    Unix time
    ÷ 30, rounded down
    As 8 bytes
  3. 3

    Mix them with HMAC-SHA1

    HMAC is a keyed fingerprint. With the secret as the key, the counter becomes 20 bytes that look random. Without the secret, nobody can predict them, and you can't work backwards from a code to the secret.

    last byte: its final 4 bits pick a position · the 4 bytes read from there

  4. 4

    Cut it down: dynamic truncation

    The last 4 bits of the HMAC give a number from 0 to 15. Read 4 bytes starting at that position, then clear the very first bit so the number can never be negative.

    Position
    4 bytes read
    First bit cleared

    Keep the last six digits

    Divide by 1,000,000 and keep the remainder, adding leading zeros if needed. That's the code on the screen.

What the QR code holds

The setup QR code is just text. This is the one the demo secret would make:

totp
Time-based codes. hotp would use a press counter instead.
Label
The service and account name your app shows.
secret
The shared secret. Anyone who sees it can make your codes forever.
algorithm, digits, period
SHA1, 6 and 30 are the defaults almost every service uses.

Never paste a real 2FA secret or setup QR code into any website, this one included. This page has no box for one on purpose.

What these codes protect against

  • A stolen or reused password on its own. The attacker also needs a code made in the last 30 seconds or so.
  • Codes intercepted in transit. None are sent to you, so there's no text message to redirect and nothing for a SIM swap to capture.
  • Replay. A careful server accepts each time step only once, so a code that's already been used is dead.

What they don't protect against

  • Real-time phishing. A fake login page can pass your code to the real site within seconds. Passkeys and security keys (FIDO2) stop this because they check the website's address.
  • Leaked secrets. A screenshot of the QR code, a database breach or malware on the phone gives away codes forever. If your app backs up to the cloud, protect that account well.
  • Losing the phone. Keep the backup codes the site gives you somewhere safe and offline.

If you run the server

  • Accept only the current step plus or minus one, and refuse a step that has already been used.
  • Rate-limit attempts. Six digits is only a million combinations.
  • Store secrets encrypted, compare codes in constant time, and use a well-tested library.
  • Offer passkeys as well, for phishing resistance.

How this page protects you

  • The page loads nothing from other websites. Its one library, three.js 0.170.0, is copied into the project. The GitHub advisory database shows no known vulnerabilities for this version.
  • A Content Security Policy only lets the browser run scripts and styles from this site. Inline code, network connections, forms and plugins are all blocked.
  • Demo secrets come from crypto.getRandomValues, a cryptographically secure source. They stay in memory only and disappear when you close the tab.
  • HMAC runs in the browser's built-in Web Crypto API. The page doesn't implement its own SHA-1.
  • No trackers, cookies, storage or input boxes. Text is written with textContent, never innerHTML or eval.
  • GitHub Pages can't send security headers, so the page can't stop other sites from framing it. There's no login or real data on it, so there's nothing to steal that way.
